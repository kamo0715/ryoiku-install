# リリース配布・更新ルール

このリポジトリは、ロリポップ向け療育カリキュラム管理システムと旧Ubuntu/Docker更新スクリプトの配布元です。
GitHubの **Releases** にバージョンごとの配布ZIPを追加する仕組みを導入しました。

## これまでの版

- **v2.2〜v2.8**：既存の自己完結型 `.sh` インストーラー／アップデーター。`bash -n` で構文確認し、内蔵ZIPを抽出して整合性を検証してから配布。v2.8 は固定コミット参照型のため関連ファイルを配布。
- **v2.9**：保存されているLITALICOマッピング差分ZIP（完全版ではありません）。
- **v2.10**：保存済みの独立した完全版パッケージを確認できていないため、リリース対象外。
- **v2.11〜v2.20**：保存済み完全版ZIPから版別のアプリソースを取り出した `release-sources/v2.x.tar.gz` を利用して、GitHubに30分割で保存済みのv2.20完全版ZIPから共通依存ライブラリを取り出し、版別ソースと組み合わせて完全配布ZIPをビルド。

## 今後の完全版を追加するには

1. 新しい完全版ZIPを手元で完成させ、実利用者データ・`.env`・秘密鍵・APIキーがないことを確認します。
2. `release-sources/v2.xx.tar.gz` に依存ライブラリを除くアプリ一式を保存し、`release-sources/manifest.json` に元ZIPの名前・SHA-256・スナップショット名を追加します。新しい依存関係が必要な場合は、再構成の基準となる完全版ZIPとビルド手順も更新します。
3. `main` にコミット・プッシュすると `.github/workflows/publish-releases.yml` が起動し、`v2.xx` の GitHub Release を作成して完全版ZIPと `SHA256SUMS.txt` を添付します。
4. 既存リリースのファイルは勝手に上書きしません。バージョンに変更があれば **新しいタグ**を採番してください。失敗時はGitHubのActions画面から再実行できます。

GitHubのActionsが有効で、ワークフローに `contents: write` が許可されている必要があります。使用したGitHub Actionsの成功とReleasesへの添付はGitHub側で確認してください。

### 重要な互換性

`v2.2〜v2.9` は旧Linux/Docker版、`v2.11〜v2.20` はロリポップFTPS版です。**違う環境用のZIPや `.sh` を混ぜて上書きしないでください。**

### 保存版と再ビルド版の違い

GitHubに保存される`release-sources/v2.xx.tar.gz`は当時の完全版ZIPの**アプリ本体と付属ドキュメント**のスナップショットであり、ビルド時にコミット済みのv2.20完全版ZIPから元のPythonライブラリを追加します。そのため、完成したZIPは元の保存版と**ファイル単位の主要ソースは一致**しますが、ZIPメタデータ等により **v2.11〜v2.19は元ZIPとバイト単位の一致は保証しません**（v2.20は元のZIPそのものを復元します）。元ZIPのSHA-256は参考としてmanifestに記載します。

新規導入の場合は完全版ZIPを使用します。既存環境の更新では事前バックアップを行い、**適用元バージョンが明記された差分ZIP**を使用してください。
