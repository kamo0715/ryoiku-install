# ロリポップ導入・更新時の注意

## 新規導入
1. `docs/release-v2.20/README_はじめに.md` と既存の導入マニュアルを読んでください。
2. ロリポップの契約・Python/CGI対応と必要なPython依存ライブラリの実行環境を確認してください。
3. `deploy/` はアプリのソース部分です。配布済みの完全版ZIPには `vendor/` など約1,400件の依存ファイルが入っています。GitHub上の `releases/v2.20/complete_zip_parts/` を `python3 tools/assemble-v2.20.py` で復元すれば同一の新規導入用ZIPを得られます。**`deploy/` のソースだけでは完全版の代替になりません。**
4. FTPではなくFTPSで配置します。`_private` 下のファイルにブラウザからアクセスできないことを確認してください。
5. 初期管理者セットアップ、職員アカウント、ロールの動作確認を行います。
6. 架空データで活動スケジュール、職員用・関係機関用・利用者用PDF/Word/Excelの出力、AI送信プレビューを検証してください。

## 差分更新

| 現在のバージョン | 推奨する操作 |
|---|---|
| v2.19 | `patches/v2.20/` の3ファイルを設置済みの対応パスへ上書き |
| v2.18 | `patches/v2.19/` を適用してから `patches/v2.20/` を適用（途中検証が必要） |
| それ以前 | 差分を飛び越して適用しない。既存アプリとデータのバックアップ後、互換性を確認して移行計画を立てる |

### 禁止・注意
- 実運用サイト全体へ全機能ZIPを無条件で上書きしない。
- 実際の児童・保護者情報、DB、`.env`、APIキー、復旧コードをGit管理しない。
- AIへ送る前に匿名化プレビューを職員が確認する。
- 出力した利用者用スケジュールに職員の観察・評価・個別支援の秘匿情報が入っていないか確認する。
- 通信・ログイン・ファイル権限・出力PDFのページ数・印字崩れをチェックする。
- 自動スケジュール短縮を想定せず、長すぎる活動名は出力前に職員が編集する。
